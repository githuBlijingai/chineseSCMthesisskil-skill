# AI 协作提示词模板

所有提示词默认先读取：

1. `standard-profile.yaml`
2. `thesis-ai-spec.yaml`
3. `figure-registry.yaml`
4. `paper-context/evidence/` 中的证据索引
5. 当前章节正文和证据材料

如果学校模板与本套件默认规则冲突，必须以学校模板为准。

## 1. 论文结构检查

```text
请读取 standard-profile.yaml、thesis-ai-spec.yaml 和当前论文目录，检查章节层级是否符合该论文类型。

输出：
1. 学校模板中必须保留的结构
2. 缺失章节
3. 章节顺序问题
4. 小节命名不一致问题
5. 需要新增、合并或删除的章节
6. 需要新增或调整的图表、公式、表格

要求：
- 只基于已提供材料，不要编造学校要求。
- 如果论文类型不明确，先列出可判断依据和需要确认的信息。
```

## 1.5 程序证据抽取

```text
请先检查项目中是否已有 paper-context/evidence/。
如果没有，请运行 chinese-thesis-workbench 的 scripts/evidence/build_project_evidence.py。

然后读取：
- project-evidence.json
- code-structure.md
- tech-stack.md
- api-list.md
- database-schema.md
- test-results.md

输出：
1. 可用于论文的真实技术栈
2. 可用于架构图的模块边界
3. 可用于数据库设计的表/实体线索
4. 可用于接口说明的 API 线索
5. 可用于测试章节的证据
6. 仍需人工确认的源码事实

要求：脚本扫描结果只是索引，重要结论必须回看源码或用户材料确认。
```

## 2. 标准配置检查

```text
请读取 standard-profile.yaml，检查论文规范来源是否完整。

重点检查：
1. 是否填写学校模板来源
2. 是否填写参考文献标准版本
3. 是否明确学校规则优先于通用默认规则
4. 是否存在"未确认却被当成硬规则"的项目
5. 是否存在可能影响 Word/PDF 排版的高风险项

输出：
- 已确认规则
- 待确认规则
- 可用默认规则
- 不应自动修改的格式项
```

## 3. 图表规范检查

```text
请读取 figure-registry.yaml，检查每张图、表、公式是否满足：
1. 编号连续
2. 标题明确
3. 有正文引用位置
4. 有源文件、截图来源或数据来源
5. 类型正确
6. 与章节内容匹配
7. 不含隐私、调试脏数据或无关截图内容

输出可执行修改建议，并按 critical / major / minor 分级。
```

## 4. 单章改写

```text
请基于以下材料改写第X章：
- standard-profile.yaml
- thesis-ai-spec.yaml
- chapter-section-template.md
- 本章已有正文
- 本章相关图表、公式、表格
- 本章证据材料

要求：
1. 保留真实事实。
2. 改善论文语体和逻辑衔接。
3. 不新增无证据结论。
4. 不改变学校格式要求。
5. 图表必须先解释再出现。
6. 不出现"根据用户提供材料""通过分析代码"等 AI 工作流表述。
7. **禁止机械列点**：
   - 禁止使用"首先/其次/再次/最后"进行列举
   - 禁止使用"第一/第二/第三/第四"等序号排比
   - 每个小节最多使用1个列表，且列表项不超过3点
   - 优先用段落叙述，少用 bullet points
   - 避免相邻段落使用相同的句式结构（如都是"XXX是..."开头）
   - 打破等长排比，让重点内容占据更多篇幅

输出：
- 改写正文
- 修改说明
- 证据不足清单
- 需要人工确认的问题
```

## 5. 图表生成说明

```text
请根据以下输入生成可编辑图：
- 图编号：
- 图题：
- 图类型：
- 参与角色、模块、实体、变量或步骤：
- 节点关系：
- 数据流、业务流、调用顺序或研究流程：
- 所属章节：
- 证据来源：

要求：
1. 使用简洁中文标签。
2. 架构图、流程图、时序图、ER 图、模型图必须可编辑。
3. 不使用装饰性图标、复杂渐变和长段落节点。
4. 图中术语必须与正文一致。
5. 输出 draw.io XML 或 Mermaid 初稿，并说明每个节点的证据来源。
6. 证据不足时先列缺失材料，不要补造节点。
```

## 6. 终稿审查

```text
请按 ai-review-rubric.json 对论文进行终稿审查。

重点检查：
1. 学校规则优先级
2. 结构完整性
3. 章节逻辑
4. 图表与公式规范
5. 证据链
6. 参考文献闭环
7. 测试、实验或分析结果可信度
8. 学术诚信风险
9. 是否出现 AI 工作流痕迹

输出：
- 总体评分
- critical 问题
- major 问题
- minor 问题
- 建议修改顺序
- 必须人工复核的 Word/PDF 排版项
```

## 7. 文献交叉引用闭环

```text
请读取：
- paper-context/literature/reference-extraction.json
- paper-context/literature/citation-crossrefs.md
- thesis-ai-standard/templates/citation-crossref-register.yaml
- 当前正文引用位置
- 当前参考文献列表

输出：
1. 正文已有引用与文末条目的对应表
2. 文末条目但正文未引用的问题
3. 正文引用但文末缺条目的问题
4. PDF 抽取候选但尚未核验的文献
5. 与章节论点弱相关或不应引用的文献
6. 需要补充核验的作者、年份、题名、来源、DOI 或 URL

要求：候选文献不能直接当作最终参考文献；必须标注 verified / needs_check / rejected。
```

```text

然后根据报告输出：
1. 缺失文件
2. 解析失败文件
3. 仍是占位内容的关键字段
4. 可以继续写作的部分
5. 必须先补齐的材料
```

## 9. AIGC 风格风险报告

```text
Use $chinese-thesis-workbench，请读取当前章节草稿，运行 AIGC style-governance 模块。

要求：
1. 先输出风格风险报告，不要直接改写。
2. 按段落列出命中的公式化表达、模糊归因、空泛结论、枚举过密、节奏重复等问题。
3. 标注 high / medium / low 风险。
4. 单独列出 needs_source 和 needs_evidence。
5. 给出建议修改顺序。

注意：目标是提升学术写作质量，不承诺规避任何检测器。
```

## 10. 基于报告定向改写

```text
请基于 aigc-style-report.md 和 aigc-style-review.yaml 只修改高风险段落。

要求：
1. 保留原有事实、数据、引用和论文观点。
2. 不新增未核验来源、实验、项目事实或 DOI。
3. 删除空泛评价句，改为具体结论、限制或后续工作。
4. 模糊归因必须补真实来源或标注 needs_source。
5. 输出改写正文、关键改动说明、仍需补证据清单。
```

请输出：

## 12. Word 批注读取与修订

```text
Use $chinese-thesis-workbench，请先运行 scripts/docx/extract_docx_comments.py 读取 Word 文档批注，生成 paper-context/word-comments/word-comment-todos.md。

然后：
1. 按批注类型分组：内容、结构、引用、格式、图表、证据不足。
2. 对每条批注给出处理策略：resolved / blocked / skipped。
3. 能直接修改的批注，按 chinese-thesis-workbench DOCX 规则修改 Word 文档。
4. 需要新增事实、数据或引用的批注，不要编造，标注 needs_evidence 或 needs_source。
5. 修改后更新 docx-revision-log.md 和 paper-context/workflow/revision-log.md。
6. 输出已解决批注、未解决批注、修改后的文档路径和需要人工复核的内容。
```

# 单片机/嵌入式论文专用提示词

## MCU-1. 单片机论文结构检查

```text
请读取 chapter-profile-mcu.yaml，检查当前单片机论文的章节结构是否符合专用配置。

重点检查：
1. 是否使用单片机专用章节标题（如"系统方案与关键技术"而非"相关技术"）
2. 硬件设计章节是否包含：主控单元、电源、传感器接口、通信接口、PCB
3. 软件设计章节是否包含：开发环境、主程序架构、功能模块、中断处理、通信协议
4. 每章段落长度是否符合 short(50-120字) : medium(200-350字) : long(400-600字) = 3:5:2 的比例

输出：
- 结构符合度评分
- 缺失的必需小节
- 段落长度分布建议
- 需要调整的逻辑衔接点
```

## MCU-2. 内容密度检查

```text
请读取当前单片机论文章节，按 chapter-profile-mcu.yaml 的 content_density_requirements 检查：

1. 每段是否至少包含2个技术关键词（如STM32F103、GPIO、USART等）
2. 每段是否至少包含1个具体参数（如72MHz、3.3V、9600波特率等）
3. 是否出现机械列点（"首先...其次...再次...最后"）
4. 相邻段落字数差异是否>30%

输出：
- 技术关键词密度报告
- 段落均匀度分析
- 发现的机械表达列表
- 具体修改建议（给出替换前后的对比）
```

## MCU-3. 硬件章节写作

```text
请基于 chapter-profile-mcu.yaml 的 chapter_3 配置，撰写/改写硬件电路设计章节。

必须遵守：
1. 段落长度按 [100, 250, 450, 250, 250, 100] 分布（以3.1节为例）
2. 每段必须包含：芯片型号或电路参数
3. 禁止空泛描述如"电路设计很重要"，必须具体到：
   - 芯片型号（如STM32F103C8T6）
   - 引脚号（如PA0、PB5）
   - 元件参数（如10KΩ、100nF）
   - 电压/频率值

逻辑衔接要求：
- 段落开头使用："为实现XX功能..."、"基于YY芯片的ZZ特性..."、"考虑到AA约束..."
- 段落结尾必须与下段形成逻辑链

证据绑定：
- 每个电路描述必须引用：原理图截图、芯片手册、或实物照片
- 无证据的描述标记为 [needs_evidence]
```

## MCU-4. 软件章节写作

```text
请基于 chapter-profile-mcu.yaml 的 chapter_4 配置，撰写/改写软件程序设计章节。

必须遵守：
1. 段落长度按配置要求分布
2. 至少包含5个代码块
3. 代码块必须包含：初始化配置、主循环逻辑、中断服务、关键算法
4. 每段代码必须有详细注释说明

内容要求：
- 不描述"代码实现了什么功能"
- 描述"如何通过代码实现功能"，包括：
  - 寄存器配置值及含义
  - 状态机状态转换条件
  - 中断优先级设置
  - 缓冲区大小及原因

禁止：
- 整段都是代码无说明
- 整段都是说明无代码
- 代码和说明分离
```

## MCU-5. 逻辑衔接优化

```text
请读取当前单片机论文，使用 chapter-profile-mcu.yaml 的 logical_transitions 模板优化段落衔接。

检查项：
1. 硬件到软件过渡是否使用指定衔接语
2. 模块间是否有承上启下
3. 理论与实践是否有逻辑连接
4. 结果到分析是否有推导关系

输出：
- 当前衔接薄弱点列表
- 推荐的衔接语句
- 优化后的段落过渡
```

## MCU-6. AIGC风格治理（单片机专用）

```text
请读取当前单片机论文章节，按 chapter-profile-mcu.yaml 的 aigc_style_rules 检查：

### 强制禁止列表（绝对禁止）
以下表达绝对禁止出现，发现必须重写：
- ❌ "首先...其次...再次...最后"
- ❌ "第一...第二...第三...第四"
- ❌ "一是...二是...三是"
- ❌ "1....2....3...."（段落开头用数字列点）
- ❌ "综上所述"（同一章内使用超过1次）
- ❌ "具有重要意义"、"具有重要价值"（空话）
- ❌ "本文设计的系统"（冗余表述，直接用系统名称）

### 段落结构强制要求
每章段落长度必须按以下模式分布，禁止机械均匀：
- 短段落(50-120字): 30% - 仅用于过渡、承上启下
- 中段落(200-350字): 50% - 主体技术内容
- 长段落(400-600字): 20% - 详细分析、对比论证

连续两段字数差异必须 >30%，否则重写较长段落，拆分或压缩内容。

### 图片强制描述规则（每张图必须遵守）
1. **位置**: 图片上方独立段落，格式严格："如图X-X所示，..."
2. **字数**: ≥50字，必须有实质内容
3. **内容三要素**: 
   - 图中是什么（元件/电路/界面）
   - 关键部件说明（型号、参数、接口）
   - 功能/工作原理简述

示例（正确）：
"如图3-1所示，人体红外检测模块采用HC-SR501传感器，工作电压5V，
检测距离3-7米，输出数字信号。模块上设有灵敏度调节电位器，可
根据实际环境调整检测范围。"

示例（错误）：
"人体红外检测模块如图3-1所示。"（字数不足，内容空洞）

### 必须出现的元素
- 每章至少1次芯片具体型号（如STM32F103C8T6）
- 每节至少1次具体参数值（如72MHz、3.3V）
- 每段至少2个技术关键词
- 技术描述必须有数据支撑，禁止空泛

### 段落开头多样化
检查段落开头词，避免重复。推荐开头：
- "为实现XX功能，..."
- "针对XX问题，..."
- "考虑到XX约束，..."
- "测试结果表明，..."
- "与XX方案相比，..."
- "基于上述分析，..."

禁止连续两段使用相同开头词。

输出：
- 风险段落列表（含具体违规内容）
- 机械分点检测结果
- 图片描述不足列表
- 具体修改建议
- 修改后的段落示例
```
